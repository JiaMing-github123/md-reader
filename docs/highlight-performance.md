# 长 Markdown 代码高亮优化验证

验证日期：2026-10-09。基线提交：`94f315d3c8648b320e214862e75fd678dc49017f`。

## 测量方式与热点

使用生成的代表性长文：166,712 个 UTF-16 字符、2,881 行、120 个章节和 120 个 TypeScript 代码块，每块约 923 字符、17 行；夹具由脚本生成到 `.tools/highlight-perf/representative.md`。没有用户提供的实际卡顿文件。

在同一台机器的 Edge 154.0.4258.62、1180 × 760 视口中运行生产构建的真实 App，禁用开发 StrictMode 的重复执行。Tauri 文件读取、文件选择和剪贴板接口使用内存模拟；没有访问真实文档或修改系统剪贴板。基线源码通过 `git show` 在测试构建中替换，工作区源码不回退。

插桩测量 `PrismLight` 组件函数的调用次数与耗时，包括语法处理和 React 元素构造，不包括后续 DOM 提交。Markdown 解析单独计时，Long Task API 记录页面主线程长任务。以下是配对运行结果，毫秒数会随机器和文档变化。

| 操作 | 修改前高亮次数 / 耗时 | 修改后高亮次数 / 耗时 |
| --- | ---: | ---: |
| 首次打开 | 120 / 3,401 ms | 1 / 4.8 ms |
| 复制状态变为 Copied 再复位，增量 | 2 / 65 ms | 0 / 0 ms |
| 五次滚动操作，增量 | 0 / 0 ms（已全部高亮） | 15 / 14.6 ms（按需高亮） |
| 进入编辑预览，增量 | 120 / 3,220 ms | 1 / 1.2 ms |
| 连续 8 个输入事件后的预览更新，增量 | 120 / 3,239 ms | 0 / 0 ms（代码未变） |

两边连续输入都仅触发一次延迟预览解析；首次 Markdown 解析分别为 43 ms 和 39.6 ms。首次渲染长任务从 3,843 ms 降到 170 ms，进入编辑预览的长任务从 3,655 ms 降到 126 ms。基线普通滚动没有重跑正文解析，上一轮 memo、稳定回调及预览隔离仍有效。

## 实现与边界

- `CodeBlock`、代码内容和实际高亮各有 memo 边界。复制反馈只更新工具栏，预览中未改变的代码保留已有节点。
- 阅读区和编辑预览显式传入各自的滚动容器。每个容器共享一个 IntersectionObserver，提前 300 px 排队；每帧最多启动一块，快速离开或卸载时取消未完成的排队任务。
- 未高亮、未知语言和超大代码块均显示完整 `<pre><code>` 文本。完成高亮后离开视口不还原，代码或语言改变会使旧结果失效；文件切换重新挂载文章以清理旧状态。
- 沿用原有 oneLight / oneDark 配色与语言注册、别名，改用 token CSS，避免每个 token 重复计算内联样式。主题只改变文章属性，已高亮的内容不重新分词，活动搜索也不重建。
- 普通和高亮内容共用字体、行高、padding、tab-size 和白空格处理。样本切换前后高度均为 473.953125 px，字体为 14.28 px，行高 23.562 px，padding 为 16 / 17.6 / 18.4 px。
- 没有引入虚拟滚动、章节分块、Worker、新依赖或渲染库替换。

### 高亮上限

只有同时满足 **不超过 20,000 字符、400 行** 的支持语言代码块才允许高亮；超出任一上限保留普通文本，完整复制和搜索继续工作。

依据是六种语法的抽样（TypeScript、JSON、YAML、TSX、Markdown、PowerShell）：每个规模先预热一次，再取三次中位数，仅测高亮准备，不含 DOM 挂载。

| 语法 | 5,000 字符 | 20,000 字符 | 50,000 字符 |
| --- | ---: | ---: | ---: |
| TypeScript | 3.5 ms | 13.7 ms | 36.6 ms |
| JSON | 3.6 ms | 16.7 ms | 46.3 ms |
| YAML | 4.0 ms | 21.5 ms | 55.3 ms |
| TSX | 6.4 ms | 20.7 ms | 60.7 ms |
| Markdown | 2.5 ms | 10.6 ms | 30.3 ms |
| PowerShell | 1.7 ms | 7.4 ms | 21.5 ms |

字符上限避开已明显较慢的大块；行数上限另外控制短行密集文本的 token 节点和布局成本，例如 20,000 字符 YAML 样本有 1,464 行，会被行数上限拦住。上限是保守的成本控制，不能保证每种复杂语法都在一帧内完成。已验证 20,000 字符以上和 401 行但字符数很少的块保持全文普通文本。

### 搜索兼容

MutationObserver 只观察正文的文本和子节点变化，排除复制工具栏、SVG、script 和 style。转换时清除失效的 Text/Range 引用并标记索引为脏；没有搜索时不扫描，活动搜索将一批转换合并到 150 ms 的尾部防抖后重建，导航则按需立即刷新。

代码/段落建立连续文本与 Text 节点偏移映射，因此 `const searchable`、`active: true` 等跨 token 搜索不会漏匹配。保持当前结果序号并重新绘制 CSS Highlight；索引刷新不把手动滚动拉回旧匹配，只有新搜索或下一项/上一项导航才滚动。

## 验证结果及限制

`check`、`build` 和 `git diff --check` 通过。本机没有 npm 可执行文件，实际使用已有 pnpm 执行 package.json 中与 `npm run check` / `npm run build` 相同的脚本，禁用其依赖自动安装；没有改动依赖或锁文件。

37 项浏览器回归断言通过，覆盖：屏幕外完整文本、快速滚动、重入缓存、字体和高度、明暗/系统主题、搜索中的主题切换、跨 token 匹配、转换后所有 Range 仍连接当前 DOM、合并重建、复制无重建、上一项/下一项跳转与循环、2,000 项上限、预览独立滚动、连续输入、真实键盘输入、代码和语言更新、纯编辑布局、最新预览恢复、文件切换、大小回退、别名、未知语言、完整复制及 Unicode 搜索。

真实键盘追加 6 个字符的测试约 209 ms，包含测试主动设置的每键 20 ms 间隔；预览显示最新输入，未重新高亮未改变的代码。这是短输入烟测，不代表长时间连续编辑的延迟分布。早期使用 Playwright `.fill()` 整篇替换 16 万字符时，前后均有约 9 秒长任务；改用输入事件与真实少量按键后没有该现象，不据此宣称日常输入仍卡顿。

剩余主要成本是全文 Markdown 解析（本夹具约 33–47 ms）及全量 DOM 的创建、布局和提交（首次渲染仍有约 170–194 ms 长任务）。已访问的高亮节点会保留，因此最终遍历全文的 DOM 规模仍然很大。本轮没有对这些环节扩大修改范围。

未重新打包或实测 Tauri 原生 EXE、系统剪贴板及 Clipboard API 失败后的 execCommand 回退；没有实测用户的实际卡顿文档或长期输入。浏览器回归不等同于原生全部功能验证。

## 复现

需要已安装的项目依赖，以及可用的 Playwright 和 Edge。脚本默认使用 Codex 已有的 Playwright 运行时；其他环境可通过 `MD_READER_PLAYWRIGHT_MODULE` 指定模块路径，通过 `MD_READER_BROWSER` 指定 Chromium/Edge 可执行文件。无需向项目添加依赖。

按顺序运行，三次运行共用测试输出目录：

```powershell
node scripts/highlight-performance/run.mjs before 94f315d3c8648b320e214862e75fd678dc49017f
node scripts/highlight-performance/run.mjs after
node scripts/highlight-performance/run.mjs regression
```

输出在 `.tools/highlight-perf/`：`before.json`、`after.json`、`regression.json`、代表性文档与截图。所有插桩只存在于测试构建中。
